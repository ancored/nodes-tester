# SQLite-хранилище

[`nodes_tester`](README.ru.md) связывает данные по ключу доступа из тега ноды
`[node_crc.cred_crc]` (колонка `crc`): CRC настроек сервера и CRC учётных данных (см.
[`naming`](../naming/README.ru.md#ключ-ноды)). История сохраняется при изменении отображаемого
имени; новый доступ того же сервера имеет тот же `node_crc` (колонка `nodes.node_crc`).

## Режим работы

Storage открывает одно соединение SQLite с `check_same_thread=False`, включает WAL и
защищает составные операции блокировкой. Пишут тестер, резерв и сборщик трафика; dashboard
читает базу параллельно.

Версия схемы хранится в `meta.schema`. Базу другой версии Storage при открытии
переименовывает в `<файл>.v<версия>-<время>` и начинает историю заново: миграций нет.

## `nodes` и присутствие

`nodes.json` из каталога данных перечитывается при изменении mtime. Storage читает
`outbounds` и `endpoints`, исключает служебные группы и сверяет ключ из тега с пересчитанным
(`crc_ok`). Страну ноды пишет не сборка, а conn-тест: успешный замер обновляет `country` у всех
доступов того же `node_crc`.

`title` — имя ноды в подписке (`title` из `raw/router.json`: по ключу доступа, а если учётные
данные с прошлой сборки сменились — по `node_crc`; у дублей — первое). Обновляется при каждом изменении raw, в том числе после опроса подписок без сборки; у
ушедшей из подписки ноды остаётся последнее имя. У ноды с `detour` ключ в сборке другой, имени у
неё нет.

`present = 1` означает, что нода есть в текущем файле. Исчезновение из подписки меняет
присутствие, но не удаляет историю сразу. `banned = 1` означает ручное исключение из
следующих проверок; бан не меняет `present`.

## Результаты и рейтинг

Один тест создаёт строку `results` с временем, ключом, именем теста, `ok`, URL, JSON метрик и
ошибкой. У тестов свои сроки годности, поэтому последние результаты одной ноды бывают разного
времени; dashboard показывает время у каждого.

`scores` хранит текущую строку ноды. `score_history` дописывается после каждого замера и служит
для графиков и анализа ухода ноды.

Формула описана в [`SCORING.md`](SCORING.ru.md).

## Трафик

TrafficCollector держит подписку `SubscribeConnections` API-сервиса sing-box. События
приходят на каждое соединение: открытие, приросты байт раз в `storage.traffic.poll`
и закрытие с итогом. Поэтому учитываются и короткие соединения, которые закрылись
между обновлениями. Трафик тестера (цепочка с `nodes-tester`) пишется отдельно
(`is_tester=1`). Раз в `storage.traffic.flush` дельты сбрасываются в `traffic`, агрегаты
направлений — в `endpoints`. После переподключения к API итоги уже открытых соединений
служат точкой отсчёта и повторно не считаются.

Счётчики показывают доступный период хранения, а не автоматически «сегодня» или последние
24 часа. При ошибке записи накопленные дельты возвращаются в буфер.

## Пауза и карантин

`garbage` хранит текущее ограничение:

- `reason = backoff` — пауза после провала GATE до времени `until`;
- `reason = garbage` — карантин до времени `until`;
- `streak` — число последовательных провалов.

Состояние переживает перезапуск. Успешный GATE очищает ограничение.

## Очистка

`cleanup()` удаляет ноды, отсутствующие дольше `storage.retention`, и связанные с ними строки
во всех таблицах. Активно тестируемая или присутствующая нода не должна исчезать из-за
старого mtime файла.

WAL и освобождение логических строк не уменьшают файл немедленно. Для физического сжатия
используется `VACUUM`. Его выполняет сам тестер по расписанию `storage.vacuum` (по умолчанию раз
в 30 дней в 04:00, отсчёт — с первого запуска), в отдельном потоке на своём соединении: запись в
базу на это время ждёт. После `VACUUM` журнал WAL сбрасывается в файл и обрезается. Итог —
`meta['vacuum']` (время, причина, размер до и после, длительность или ошибка; после ошибки —
повтор через сутки); в админке («Настройки») он виден вместе с кнопкой «Выполнить сейчас».

Вручную, при остановленном тестере:

```sh
python3 -m nodes_tester -c config/config.json --vacuum
```

На пакетной установке: `nodes-tester vacuum`.

## Резервная копия

Не копируйте только `stats.db` у работающего процесса: часть данных может находиться в
`stats.db-wal`. Безопасные варианты:

1. остановить тестер и скопировать файлы базы;
2. использовать SQLite backup API;
3. восстановить копию отдельно и выполнить проверку целостности.

В базе могут находиться адреса нод, история подключений и эксплуатационные данные. Не
публикуйте её вместе с отчётом об ошибке.
