# SQLite-хранилище

[`nodes_tester`](README.md) связывает данные по CRC из тега ноды. CRC рассчитывается из
настроек, поэтому история сохраняется при изменении отображаемого имени, пока конфигурация
самой ноды остаётся прежней.

## Режим работы

Storage открывает одно соединение SQLite с `check_same_thread=False`, включает WAL и
защищает составные операции блокировкой. Пишут поток прогона и сборщик трафика; dashboard
читает базу параллельно.

Базы прежних версий обновляются добавлением недостающих колонок.

## Таблицы

| Таблица | Содержимое |
|---|---|
| `nodes` | идентичность, payload, адрес, присутствие и ручной бан |
| `endpoints` | направления реальных соединений и объём трафика |
| `results` | сырые результаты тестов по проходам |
| `traffic` | временной ряд входящего и исходящего трафика |
| `scores` | текущий рейтинг, компоненты, EWMA и heavy veto |
| `score_history` | динамика рейтинга по проходам |
| `garbage` | пауза, карантин, streak и номер следующей попытки |
| `activations` | история применённых переключений |
| `switch_state` | активная нода, сроки и счётчики региона |
| `switch_recent` | недавно использованные кандидаты |
| `switch_activations` | накопительное число выборов ноды |
| `node_events` | добавление, удаление, пауза, карантин и восстановление |
| `meta` | служебные значения, например сквозной номер прохода |

## `nodes` и присутствие

Файл из `storage.nodes_file` перечитывается при изменении mtime. Storage читает
`outbounds` и `endpoints`, исключает служебные группы и проверяет CRC payload.

`present = 1` означает, что нода есть в текущем файле. Исчезновение из подписки меняет
присутствие, но не удаляет историю сразу. `banned = 1` означает ручное исключение из
следующих проверок; бан не меняет `present`.

## Результаты и рейтинг

Один тест создаёт строку `results` с временем, номером прохода, CRC, именем теста, `ok`,
URL, JSON метрик и ошибкой. Метрики разных тестов имеют собственное время; dashboard не
должен представлять их как один одновременный снимок без проверки прохода.

`scores` хранит текущую строку ноды. `score_history` дописывается после прохода и служит
для графиков и анализа ухода ноды.

Формула описана в [`SCORING.md`](SCORING.md).

## Трафик

TrafficCollector держит подписку `SubscribeConnections` API-сервиса sing-box. События
приходят на каждое соединение: открытие, приросты байт раз в `storage.traffic.poll_interval`
секунд и закрытие с итогом. Поэтому учитываются и короткие соединения, которые закрылись
между обновлениями. Трафик тестера (цепочка с `nodes-tester`) пишется отдельно
(`is_tester=1`). Раз в `flush_interval` дельты сбрасываются в `traffic`, агрегаты
направлений — в `endpoints`. После переподключения к API итоги уже открытых соединений
служат точкой отсчёта и повторно не считаются.

Счётчики показывают доступный период хранения, а не автоматически «сегодня» или последние
24 часа. При ошибке записи накопленные дельты возвращаются в буфер.

## Пауза и карантин

`garbage` хранит текущее ограничение:

- `reason = backoff` — пропуск заданного числа следующих проходов;
- `reason = garbage` — карантин до времени `until`;
- `streak` — число последовательных провалов;
- `until_pass` — сквозной номер прохода следующей попытки.

Состояние переживает перезапуск. Успешный GATE очищает ограничение.

## Очистка

`cleanup()` удаляет ноды, отсутствующие дольше `retention_days`, и связанные с ними строки
во всех таблицах. Активно тестируемая или присутствующая нода не должна исчезать из-за
старого mtime файла.

WAL и освобождение логических строк не уменьшают файл немедленно. Для физического сжатия
используется отдельный `VACUUM`:

```sh
python3 -m nodes_tester -c config/config.json --vacuum
```

На пакетной установке: `nodes-tester vacuum`.

## Резервная копия

Не копируйте только `stats.db` у работающего процесса: часть данных может находиться в
`stats.db-wal`. Безопасные варианты:

1. остановить тестер и скопировать файлы базы;
2. использовать SQLite backup API;
3. восстановить копию отдельно и выполнить проверку целостности.

В базе могут находиться адреса нод, история подключений и эксплуатационные данные. Не
публикуйте её вместе с отчётом об ошибке.
