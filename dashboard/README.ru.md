# dashboard

`dashboard` служит HTTP-бэкендом веб-админки. Он отдаёт собранный Vue SPA, читает SQLite,
проверяет токен администратора и подключает API просмотра, конфигурации и управления.

Пользовательская работа с интерфейсом описана в [`docs/USAGE.md`](../docs/USAGE.ru.md).
Этот файл описывает границы Python-модуля.

Скриншоты всех разделов в светлой и тёмной теме находятся в
[`docs/screenshots`](../docs/screenshots/README.ru.md).

## Два режима

### Встроенный

При `admin.enabled: true` сервер создаётся внутри `nodes_tester.Runner`. Ему доступны
Runner, Switcher, Scoreboard и Storage. В этом режиме работают:

- статус тестера;
- тестирование всех нод по запросу, не дожидаясь сроков годности;
- живой журнал;
- бан, карантин и снятие ограничений;
- ручной выбор ноды в группе;
- `VACUUM` базы по запросу;
- чтение и запись `config.json`.

### Отдельный процесс

```sh
python3 -m dashboard -c config/config.json --host 127.0.0.1 --port 8088
```

Отдельный процесс открывает базу для чтения и может редактировать `config.json` по токену, но не имеет живого Runner. Управление тестированием, журналом и селекторами в таком
режиме недоступно.

## Доступ

Большинство читающих API доступны без токена только при `admin.public_read: true`. История
конвейера, его журналы и исходные файлы sing-box всегда требуют токен: в них могут быть
адреса подписок и другие рабочие данные. Запись и действия
всегда требуют заголовок `X-Admin-Token` (или `Authorization: Bearer`), равный `admin.token`. Пустой токен отключает
операции изменения.

Админку следует публиковать только в доверенной сети или через HTTPS с дополнительной
защитой. Она показывает эксплуатационные данные, а редактор подписок работает с их URL.

## API

| Группа | Маршруты | Назначение |
|---|---|---|
| Сессия | `/api/capabilities`, `/api/session` | режим сервера и проверка доступа |
| Данные | `/api/data`, `/api/rating`, `/api/results` и другие срезы | чтение SQLite и состояния |
| Конфиг | `/api/config`, `/api/config/sections`, `/api/config/schema` | чтение и атомарная запись `config.json` (подписки, группы, тестер, конвейер — один файл): весь файл по ревизии или только изменённые разделы; схема даёт значения по умолчанию для подсказок форм |
| Варианты формы | `/api/config/subscription-options` | варианты User-Agent, заголовки Happ, HWID установки, имена проверок и типов IP, встроенные регионы, состояние подписок из raw (`sources`) |
| Группы | `/api/groups`, `/api/nodes/{crc}/groups` | состояние групп (активная нода или запасной выход, кандидаты, резерв); проверки групп для ноды с временем результатов |
| Карточка | `/api/nodes/{crc}/score-history`, `/api/nodes/{crc}/details` | история рейтинга; JSON ноды, строки для `node_crc` и `cred_crc`, пути учётных данных (details требует токен) |
| Ноды | `/api/nodes/{crc}/...` | бан, карантин и снятие ограничений |
| Переключение | `/api/groups/{group}/switch` | ручной выбор кандидата; 409 содержит `code` и `allowed_groups` |
| Runner | `/api/status`, `/api/run/tests`, `/api/logs` | состояние, тестирование по запросу и журнал |
| База | `GET /api/storage/vacuum`, `POST /api/storage/vacuum` | итог последнего `VACUUM`, следующий запуск по расписанию, размер базы; запуск вручную (токен) |
| sing-box | `GET /api/singbox/control`, `POST /api/singbox/stop`, `POST /api/singbox/start`, `PUT /api/singbox/killswitch` | состояние, аварийная остановка и запуск, включение и выключение службы killswitch роутера (только OpenWrt) |
| Уведомления | `POST /api/notify/test` | тестовое сообщение по настройкам работающего процесса |
| Конвейер | `/api/pipeline`, `/api/pipeline/run`, `/api/pipeline/runs`, `/api/pipeline/runs/{id}`, `/api/pipeline/schedule` | расписание, запуск и история; все маршруты требуют токен |
| Файлы sing-box и пресеты | `/api/singbox/files/...`, `/api/singbox/presets` | ограниченный список JSON-файлов, проверка итоговой сборки при записи базы и пресетов, revision и 20 прошлых версий, удаление пресетов |

`/api/data` сохранён как общий агрегат для совместимости. Раздельные read-маршруты удобнее
для отдельных экранов и диагностики.

Срез `traffic` отдаёт `traffic_test_download_24h`: сумму `downloaded` из результатов
`download` и `heavy_download` за последние 24 часа. Это измеренные байты тела ответов,
без служебного трафика и других тестов. `traffic_tester_totals` — весь трафик тестера за
сохранённый период из точного учёта соединений (`storage.traffic`).

Сообщения API и ошибки сервера пока на русском; сам интерфейс переводится на клиенте.

## MCP

`POST /mcp` — сервер [Model Context Protocol](https://modelcontextprotocol.io) (Streamable HTTP,
JSON-RPC 2.0) для MCP-клиентов. Работает во встроенном режиме и требует токен администратора в
`Authorization: Bearer <admin.token>` (или `X-Admin-Token`): клиент получает те же права, что
администратор в админке. Сервер не держит сессий и отвечает на каждый запрос одним JSON-ответом;
`GET /mcp` (поток SSE) не предлагается. Запрос с `Origin`, не совпадающим с `Host`, отклоняется.

Настройка клиента (обычный формат `mcpServers`):

```json
{
  "mcpServers": {
    "nodes-tester": {
      "type": "http",
      "url": "http://192.168.1.1:8088/mcp",
      "headers": { "Authorization": "Bearer <admin.token>" }
    }
  }
}
```

Инструменты вызывают те же маршруты API, поэтому проверки, ревизии и ошибки — как в интерфейсе. Длинные
списки обрезаются по `limit` с числом `_truncated`.

При подключении сервер передаёт клиенту инструкцию: как безопасно работать с инструментами, главные правила сборки
конфига sing-box и модели безопасности и ссылки на документацию работающих версий: nodes-tester — по его тегу,
настройка sing-box — работающего ядра (для `sing-box-lx` — его копия документации upstream и описание расширений).
Версию ядра сервер берёт из `sing-box version`. Пакет содержит английскую документацию (`docs/`, README модулей),
инструмент `docs` отдаёт её без доступа в интернет.

| Инструмент | Вид | Что делает |
|---|---|---|
| `overview` | чтение | возможности, версия и build-теги ядра, статус тестера, группы с кандидатами и резервом, sing-box и kill switch, конвейер |
| `list_nodes` | чтение | ноды с фильтрами по группе, провайдеру, стране, протоколу, состоянию и тексту |
| `get_node` | чтение | одна нода: идентичность, составляющие рейтинга, последний результат каждого теста, проверки групп, ограничения, события, активации, история рейтинга; `include_config` добавляет JSON outbound |
| `get_view` | чтение | готовый срез: `rating`, `history`, `results`, `traffic`, `lifecycle`, `graveyard` |
| `tester_log`, `singbox_log` | чтение | последние строки журнала тестера и файла лога sing-box (`log.output`) с фильтром по регулярному выражению |
| `pipeline` | чтение | расписание и прогоны или один прогон с журналом |
| `get_config`, `config_schema` | чтение | `config.json` с ревизией; схема раздела с описаниями и значениями по умолчанию |
| `singbox_files` | чтение | список исходных файлов sing-box и пресетов, файл с версиями |
| `docs` | чтение | документация этой версии: список с разделами, документ или только разделы по заголовку |
| `query_db` | чтение | один `SELECT` по `stats.db`: соединение только для чтения, без `ATTACH` и `PRAGMA`, кроме описания схемы, 5 с и до 5000 строк |
| `node_action` | действие | бан, разбан, карантин, снятие карантина |
| `switch_group` | действие | выбрать кандидата в группе |
| `run_tests` | действие | проверить все ноды сейчас |
| `run_pipeline` | действие | запустить конвейер (`dry_run` — только сборка и проверка), по желанию дождаться конца и вернуть журнал |
| `update_config` | действие | заменить разделы верхнего уровня `config.json` (тестер перезапустится) |
| `edit_singbox_file` | действие | записать, восстановить версию или удалить исходный файл sing-box по ревизии |
| `singbox_control` | действие | остановить и запустить sing-box, включить и выключить службу kill switch |
| `call_api` | действие | любой маршрут `/api/...`, не покрытый выше |

Читающие инструменты помечены `readOnlyHint`, способные нарушить связь или перезапустить службу —
`destructiveHint`, чтобы клиент мог спросить подтверждение перед ними.

Сам клиент часто ходит к своей модели и к `/mcp` через этот же роутер. Перезапуск sing-box конвейером
рвёт эту связь до минуты, запись конфига делает `/mcp` недоступным примерно на 10 с, а `singbox_control stop`
при включённом kill switch отрезает клиента, пока sing-box не запустят вручную. Инструкция сервера
говорит об этом и советует давать `run_pipeline` `wait` дольше прогона.

## Работа с файлами

Редактор проверяет `config.json` тем же загрузчиком, что тестер и конвейер
(`nodes_tester.config.parse_config`): неизвестное поле или неверное значение отклоняется с путём
поля. Запись выполняется во временный файл с `fsync` и атомарной заменой, права `0600`
сохраняются.

Форма сохраняет только изменённые разделы верхнего уровня (`POST /api/config/sections`): сервер
сверяет их с тем, что было открыто, и отклоняет запись, только если по SSH или в другом окне
изменили те же разделы. Расширенный JSON сохраняется целиком по маркеру версии файла.

Страницы «Подписки и сборка» и «Настройки» редактируют один документ. На первой — подписки по
ветвям (`router`, `clients`), раздел `pipeline` и группы с проверками, на второй — тестер,
выбор нод, админка, хранение и уведомления. Неизвестные поля и переопределения сохраняются. Пустое
поле не пишется: действует значение по умолчанию из `config.schema.json`, оно показано серым.

Для обычных URL можно выбрать стандартный браузерный User-Agent, `curl`, `clashmeta`
или свою строку. Он используется только при HTTP-загрузке. Для Happ crypt-crypt5
редактируется набор `happ_headers`, включая его собственный User-Agent; значения
по умолчанию берутся непосредственно из загрузчика, отдельный `user_agent` игнорируется.

Сохранение не запускает загрузку подписок, сборку и применение sing-box. Встроенный тестер после
сохранения перезапускается сам (`/etc/init.d/nodes-tester restart` отвязанным процессом), кроме времени
работы конвейера; ответ PUT содержит `restarting` и, если перезапуска нет, `restart_note`. В пакете OpenWrt raw хранится в `/opt/nodes-tester/raw/router.json`, результат
сборки — `nodes.json` и `whnodes.json` в том же каталоге данных. Параметры подписок отдают и состояние клиентов (источник
конфига и время публикации по его токену, без самого токена) и число нод в каждой клиентской группе из
`client-candidates.json`.

JSON в карточке берётся из `nodes.json`; если фрагмента там нет, доступная
часть восстанавливается из tag и payload SQLite с пояснением об отсутствующих полях.
Ключ ноды и JSON показываются двумя цветами: настройки сервера (`node_crc`) и учётные данные
(`cred_crc`); поля вне ключа (`tag`, `domain_resolver`) без цвета. Ниже — обе строки, которые
хешируются, и проверка ключа. История рейтинга показывает все сохранённые замеры ноды с датой и временем. График показывает последние 24 значения.

## Статика и маршрутизация

`webapp.py` реализует небольшой HTTP-каркас на стандартной библиотеке Python:

- маршруты по методу и шаблону пути;
- JSON-ответы и проверку размера тела;
- авторизацию API;
- безопасную раздачу файлов из `dashboard/static`;
- SPA fallback только для URL без расширения.

Исходники интерфейса находятся в [`web`](../web/README.ru.md). В репозиторий и пакет попадает
результат сборки `dashboard/static`.
