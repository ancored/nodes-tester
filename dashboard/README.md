# dashboard

`dashboard` — HTTP-бэкенд веб-админки. Он отдаёт собранный Vue SPA, читает SQLite,
проверяет токен администратора и подключает API просмотра, конфигурации и управления.

Пользовательская работа с интерфейсом описана в [`docs/USAGE.md`](../docs/USAGE.md).
Этот файл описывает границы Python-модуля.

Скриншоты всех разделов в светлой и тёмной теме находятся в
[`docs/screenshots`](../docs/screenshots/README.md).

## Два режима

### Встроенный

При `dashboard.enabled: true` сервер создаётся внутри `nodes_tester.Runner`. Ему доступны
Runner, Switcher, Scoreboard и Storage. В этом режиме работают:

- статус текущего прохода;
- запрос внепланового прохода;
- живой журнал;
- бан, карантин и снятие ограничений;
- ручной выбор ноды региона;
- чтение и запись конфигов.

### Отдельный процесс

```sh
python3 -m dashboard -c config/config.json --host 127.0.0.1 --port 8088
```

Отдельный процесс открывает базу для чтения и может редактировать конфигурационные файлы
по токену, но не имеет живого Runner. Управление проходом, журналом и селекторами в таком
режиме недоступно.

## Доступ

Читающие API доступны без токена только при `dashboard.read_open: true`. Запись и действия
всегда требуют заголовок `X-Admin-Token`, равный `dashboard.token`. Пустой токен отключает
операции изменения.

Админку следует публиковать только в доверенной сети или через HTTPS с дополнительной
защитой. Она показывает эксплуатационные данные, а редактор providers работает с URL
подписок.

## API

| Группа | Маршруты | Назначение |
|---|---|---|
| Сессия | `/api/capabilities`, `/api/session` | режим сервера и проверка доступа |
| Данные | `/api/data`, `/api/rating`, `/api/results` и другие срезы | чтение SQLite и состояния |
| Конфиг | `/api/config`, `/api/config/schema` | чтение и атомарная запись `config.json` |
| Источники | `/api/config/providers` | чтение и запись файла `dashboard.providers_file` |
| Ноды | `/api/nodes/{crc}/...` | бан, карантин и снятие ограничений |
| Переключение | `/api/regions/{region}/switch` | ручной выбор кандидата |
| Runner | `/api/status`, `/api/run/pass`, `/api/logs` | состояние, запрос прохода и журнал |

`/api/data` сохранён как общий агрегат для совместимости. Раздельные read-маршруты удобнее
для отдельных экранов и диагностики.

## Работа с файлами

Редактор `config.json` проверяет JSON Schema и семантику через
`nodes_tester.config.load_config`. Providers проверяется тем же загрузчиком, что использует
`nodes_fetch`. Запись выполняется во временный файл с `fsync` и атомарной заменой.

Сервер использует маркер версии прочитанного файла. Если файл изменился в другом окне или
по SSH, запись устаревшего черновика отклоняется.

Сохранение providers не запускает fetch, config или применение sing-box. Фильтры
`groups_params.json` также не редактируются этим API.

## Статика и маршрутизация

`webapp.py` реализует небольшой HTTP-каркас на стандартной библиотеке Python:

- маршруты по методу и шаблону пути;
- JSON-ответы и проверку размера тела;
- авторизацию API;
- безопасную раздачу файлов из `dashboard/static`;
- SPA fallback только для URL без расширения.

Исходники интерфейса находятся в [`web`](../web/README.md). В репозиторий и пакет попадает
результат сборки `dashboard/static`.

## Карта кода

| Файл | Ответственность |
|---|---|
| `server.py` | сборка приложения, подключение API и запуск сервера |
| `webapp.py` | HTTP-каркас, маршрутизация, токен и статика |
| `data.py` | запросы и агрегаты из SQLite |
| `api_read.py` | читающие маршруты |
| `api_control.py` | действия над нодами, регионами и Runner |
| `api_config.py` | редактор `config.json` и providers |
| `api_session.py` | возможности режима и проверка сессии |
| `static/` | собранный Vue SPA |
