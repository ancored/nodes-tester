# Админка и повседневная работа

[О проекте](../README.md) · [Первый запуск на OpenWrt](../openwrt/README.md)

Это руководство описывает обновлённую админку в исходниках. Ранее опубликованный пакет v0.1.0 содержит прежний интерфейс; обновление исходников само по себе не обновляет пакет на роутере.

## Где что искать

| Задача | Раздел |
|---|---|
| Проверить состояние базы, тестера и выбор регионов | Обзор |
| Найти ноду, понять ограничения, посмотреть измерения или выполнить действие | Ноды → карточка |
| Сравнить рейтинг, результаты и качество провайдеров | Подразделы «Нод» |
| Настроить источники и узнать, как применить их | Подписки и сборка |
| Запросить проход, посмотреть его этап и журнал | Проверки |
| Разобрать историю выбора регионов | Переключения |
| Посмотреть пользовательский трафик за сохранённый период | Трафик |
| Настроить Clash API, SOCKS, тесты, переключение и хранение | Настройки |

Поиск, сортировка, фильтры и страницы таблиц сохраняются в адресе. Автообновление не сбрасывает их. Карточка ноды связана с результатами и событиями по CRC, поэтому переименование тега не разрывает историю.

## Доступ

Нажмите «Войти для управления» и введите токен из `dashboard.token` рабочего `config.json`. При установке пакета он создаётся автоматически. Это не секрет Clash API. Админка проверит токен на сервере; одного ввода строки недостаточно для доступа к действиям.

Токен хранится только до закрытия страницы, если не включить «Запомнить на этом устройстве». Эта опция сохраняет его в localStorage. «Выйти» удаляет сохранённый токен и закрывает редактор. Не включайте запоминание на чужом компьютере; используйте доверенную сеть или HTTPS, не выставляйте админку напрямую в интернет.

Отдельный `python3 -m dashboard` читает БД и позволяет редактировать файлы по токену, но не управляет Runner, не запускает проходы и не показывает живой журнал. Админка сообщает этот режим отдельно.

## Настройки и подписки

«Настройки» содержит формы подключения, плана проверок, автоматики, хранения и доступа. Форма подключения меняет первую тестовую группу; региональные и групповые переопределения остаются в расширенном JSON и могут иметь приоритет над общими параметрами.

«Подписки и сборка» редактирует файл из `dashboard.providers_file`. По умолчанию пакетной установки это `config-main/providers.json`. Поддерживаются URL/happ, файл и папка AWG; дополнительные поля существующего документа сохраняются. URL и секреты скрыты по умолчанию.

XHTTP и AWG рассчитаны на `sing-box-lx`. Обычное ядро не примет созданный для них конфиг.
Редактор providers только сохраняет источники и не настраивает фильтры: для обычного
sing-box исключите `xhttp` и `wg` в `config-main/groups_params.json`. Подробности приведены
в [руководстве по совместимости](SING_BOX_COMPATIBILITY.md).

Перед сохранением нажмите «Проверить изменения», просмотрите список полей и подтвердите запись. Сервер проверяет конфиг и записывает его атомарно. Если файл изменили в другом окне или по SSH, сохранение будет отклонено до перечитывания. Навигация, перечитывание и закрытие страницы предупреждают о несохранённом черновике; черновик не является резервной копией.

После сохранения `config.json` перезапустите использующий его процесс. Для встроенной админки OpenWrt:

```sh
/etc/init.d/nodes-tester restart
```

Сохранение `providers.json` не скачивает подписки, не собирает конфигурацию и не применяет её к sing-box. Админка не знает время последнего внешнего применения. Фильтры и группы сборки (`groups_params.json`), дополнительные ноды (`user_nodes.json`) и клиентский набор `config-wh/` редактируются отдельно через SSH.

## Обновить ноды, затем проверить

Если фрагмент интегрировали вручную, повторите сборку и применение из [первого запуска](../openwrt/README.md#3-настроить-подписку-и-собрать-ноды). Для подготовленного штатного конвейера с базой и репозиторием правил:

```sh
nodes-tester pipeline router --dry-run
nodes-tester pipeline router
```

Первая команда тоже скачивает подписки и пишет промежуточные файлы. Вторая может перезапустить sing-box и оборвать проксируемое соединение. При защитном отказе загрузки могут использоваться предыдущие данные: читайте журнал конвейера. Админка эти команды не выполняет.

«Запросить внеплановую проверку» в «Проверках» работает только с нодами, уже доступными тестеру в sing-box. Текущий проход не прерывается; повторный запрос объединяется с уже ожидающим. Интерфейс показывает этап, обработанные ноды (включая пропуски) и последний результат. Время ротации не является прогнозом завершения прохода.

## Как читать состояние и действовать

Присутствие в списке тестера, качество, ограничения и выбор переключателя — отдельные признаки. Отсутствие замеров не означает провал. Рейтинг имеет шкалу 0–100, его факторы нормированы от 0 до 1; физические значения смотрите в результатах с датой собственного замера. Тяжёлая загрузка может относиться к другому проходу.

В карточке ноды доступны действия с подтверждением:

- «Исключить» — бессрочно пропускать следующие проверки до снятия исключения. Это не удаление из подписки и не немедленная смена текущего селектора.
- «В карантин» — отложить проверки на настроенный срок `cooldown.garbage_hours`. При отключённом cooldown действие недоступно.
- «Снять ограничение» — разрешить повторную пробу со следующего подходящего прохода. Это не подтверждает исправность ноды.
- «Выбрать для региона» — переключить регион на допустимого кандидата сейчас. Автоматика продолжает работать и впоследствии может изменить выбор.

Обзор отражает состояние переключателя, не независимую проверку селекторов sing-box. История содержит последние 200 записей с датой, регионом, причиной и предыдущей нодой. «Последняя запись региона» не означает текущую активную ноду; авария без замены не считается успешным переключением.

Трафик показан за доступный сохранённый период, не за последние сутки; тестовый трафик исключён. Топ нод ограничен 10, назначений — 50. Счётчики назначений накопительные. Журнал можно приостановить и отфильтровать; после длинной паузы часть старых строк может исчезнуть из серверного буфера.

## Расписание и обслуживание

Обновление подписок имеет отдельное расписание; пакет не создаёт cron автоматически. Для подготовленного конвейера можно добавить в `/etc/crontabs/root`:

```cron
0 3 * * * nodes-tester pipeline router >> /var/log/nodes-pipeline.log 2>&1
0 4 1 * * nodes-tester vacuum
```

Перечитайте cron: `/etc/init.d/cron restart`. Для постоянных логов выберите постоянный носитель и настройте ротацию. Не запускайте второй тестер поверх сервиса. Резервную копию БД делайте после остановки либо через SQLite backup; не копируйте только `stats.db` из работающей WAL-базы.

Клиентская ветка требует собственного `config-wh/`, `clients.list`, баз клиентов и скриптов в `REPO_DIR`: сначала `nodes-tester pipeline clients --dry-run`, затем `nodes-tester pipeline clients`. Установка пакета не создаёт эту инфраструктуру.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Админка не открывается | Сервис, `dashboard.enabled`, адрес/порт, LAN-доступ, `logread -e nodes-tester` |
| Токен не принимается | Токен действующего конфига; после изменения нужен перезапуск |
| База отсутствует или отключена | `storage.enabled`, путь `storage.db_file`, запуск тестера |
| Ошибка чтения или старые данные | Ошибку в шапке; устаревший снимок не подтверждает текущее состояние |
| Нет замеров | Тестовый selector, журнал, `storage.store_results`, завершение прохода |
| Новых нод нет после сохранения | Выполнены ли загрузка, сборка и применение к sing-box |
| Выбор региона недоступен | Проверенный токен, встроенный Runner, switching, кандидат без ограничений |

В [Issues](https://github.com/andreydyadyk/nodes-tester/issues) укажите версии OpenWrt, пакета и sing-box, действие и короткую обезличенную ошибку. Удалите URL подписок, ключи, токены и приватные адреса.
