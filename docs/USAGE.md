# Админка и повседневная работа

[О проекте](../README.md) · [Установка и первый запуск](../openwrt/README.md)

Здесь описан текущий интерфейс. Веб-админка запускается вместе с тестером; адрес, порт и доступ задаются в `dashboard` файла `config.json`.

## Где что искать

| Задача | Раздел админки |
|---|---|
| Быстро посмотреть общую статистику | Обзор |
| Сравнить качество нод в регионе | Рейтинг |
| Посмотреть конкретные измерения | Результаты |
| Узнать объём пользовательского трафика и направления | Трафик |
| Разобрать паузы, карантин и качество провайдеров | Жизненный цикл |
| Посмотреть ноды, убранные провайдером из подписки | Кладбище |
| Узнать историю выбора нод | Переключения |
| Вручную переключить регион или ограничить ноду | Управление |
| Посмотреть статус тестера, запросить проверку, прочитать лог | Прогоны |
| Изменить настройки тестера или подписок | Конфиг |

Рейтинг — сводный балл качества, а столбцы `rel`, `cons`, `thr`, `jit`, `lat`, `dl` — нормированные составляющие, не физические единицы измерения. Задержку и скорость смотрите в «Результатах». У тяжёлой проверки загрузки собственная периодичность: звёздочка отмечает значение из другого прохода.

«Активная» отражает состояние выбора по данным тестера. Последняя запись в истории не заменяет проверку текущего selector в sing-box. «Нод в подписке» на текущем обзоре считается по строкам рейтинга; для состава и статусов используйте также «Управление». Трафик показан за доступную историю в БД, без тестового трафика, а не за выбранные сутки.

## Доступ и безопасное управление

Токен администратора находится в `dashboard.token` рабочего `config.json`; при установке пакета он создаётся автоматически. Введите его в поле `X-Admin-Token` в шапке. Браузер сохраняет токен локально. Пустой или неверный токен не даёт права редактировать конфиги и выполнять действия, даже если кнопка выглядит активной.

- «Активировать» меняет выбор ноды региона сейчас, но не закрепляет её навсегда: автоматический переключатель продолжает работать. Возможны изменения существующих соединений.
- «Бан» — ручное бессрочное исключение из проверок до снятия ограничения. Это не удаление ноды из подписки или файла sing-box.
- «Пауза» — автоматический пропуск следующих проходов после неудачных проверок.
- «Карантин» — временное ограничение с повторной пробой после настроенного срока. Снятие ограничения не гарантирует исправность ноды.
- «Рейтинг 0» может означать провал проверки или отсутствие достаточных измерений; смотрите результаты и лог.

Отдельный запуск `python3 -m dashboard` показывает данные из БД без живого тестера: переключения, запуск прохода и живой лог недоступны. Однако файловый редактор конфигов по токену остаётся доступен; это не полностью неизменяющий режим.

## Изменить настройки

В «Конфиге» сейчас два JSON-редактора:

- `config.json` — подключение к sing-box, тесты, переключение, хранение и админка. После сохранения перезапустите тестер на роутере: `/etc/init.d/nodes-tester restart`.
- `providers.json` — файл из `dashboard.providers_file`, по умолчанию пакетной установки `config-main/providers.json`. Сохранение не скачивает подписки и не применяет новые ноды.

Фильтры и группы сборки находятся отдельно в `config-main/groups_params.json`; дополнительных нод — в `user_nodes.json` этого набора, если вы его используете. В текущем интерфейсе редактора этих файлов нет. Клиентский набор `config-wh/` тоже не выбирается автоматически при изменении основного providers.

Перед редактированием сохраните копию рабочего файла. Не уходите со страницы с несохранённым JSON и не нажимайте «перечитать»: черновик может потеряться. Перезапуск страницы браузера не применяет изменения к работающему тестеру.

## Обновить ноды и проверить их

Обновление включает три отдельных шага: скачать подписки → собрать и применить конфигурацию sing-box → проверить загруженные ноды.

Если интегрировали фрагмент вручную, повторите сборку и применение из [первого запуска](../openwrt/README.md#3-настроить-подписку-и-собрать-ноды). Один перезапуск тестера не добавит новые ноды в sing-box.

Если у вас подготовлен штатный конвейер с базой и правилами:

```sh
nodes-tester pipeline router --dry-run
nodes-tester pipeline router
```

Выполняйте вторую команду только после проверки первой и в подходящее время: она может перезапустить sing-box. `--dry-run` не применяет боевой конфиг, но скачивает подписки и пишет промежуточные файлы. Защитный отказ загрузки может оставить конвейер на предыдущих данных; читайте сообщения, не только код выхода. При удалённом доступе через сам прокси учитывайте возможный обрыв сессии.

Кнопка «Запустить прогон сейчас» в «Прогонах» лишь запрашивает внеплановую проверку нод, уже доступных работающему тестеру. Она не запускает остановленный сервис и не обновляет подписки.

## Расписание и обслуживание

Сервис тестера включается через UCI. Обновление подписок — отдельное расписание: пакет не добавляет cron автоматически. Для подготовленного штатного конвейера можно добавить в `/etc/crontabs/root`:

```cron
0 3 * * * nodes-tester pipeline router >> /var/log/nodes-pipeline.log 2>&1
0 4 1 * * nodes-tester vacuum
```

После изменения перечитайте cron: `/etc/init.d/cron restart`. Пример запускает конвейер ежедневно в 03:00 и обслуживание БД раз в месяц. `/var/log` обычно временный; для долговременного хранения логов выберите постоянный носитель и организуйте их ротацию.

Не запускайте второй тестер поверх сервиса. Для резервного копирования остановите его или используйте штатный SQLite backup; не копируйте только `stats.db` из работающей WAL-базы. Сохраняйте также конфиги в `config_dir` и UCI. Логи и БД могут содержать приватные сведения, не отправляйте их публично целиком.

## Клиентские конфиги (необязательно)

Это отдельная ветка: источники и группы берутся из `config-wh/`, имена клиентов — из `/etc/nodes-tester/clients.list`. В подготовленном `REPO_DIR` нужны `android_clients/base_<имя>.json` для каждого клиента и `merge-configs.py`. Эта инфраструктура не создаётся установкой пакета.

Сначала выполните `nodes-tester pipeline clients --dry-run` и проверьте результат в `data_dir/clients-dry`. Для записи итоговых файлов в `/etc/sing-box-clients/` выполните `nodes-tester pipeline clients`. Подготовьте собственный способ передачи этих файлов клиентам: конвейер не устанавливает клиентское приложение. Клиентские конфиги проверяются при импорте на соответствующем клиенте, а не ядром sing-box роутера.

## Если что-то непонятно или не работает

| Симптом | Что проверить |
|---|---|
| Админка не открывается | `dashboard.enabled`, адрес и порт, запущен ли сервис, `logread -e nodes-tester`, правила доступа из LAN |
| Токен не принимается | Токен из действующего конфига; после его изменения нужен перезапуск тестера |
| Таблицы пусты | Есть ли ноды в selector `nodes-tester`, завершены ли проверки, верен ли путь `storage.db_file`; пустота также возможна при ошибке чтения БД |
| Подписка сохранена, но новых нод нет | Выполнены ли загрузка, сборка и применение к sing-box; кнопку проверки не путать с обновлением |
| Регион не переключается | `switching.enabled`, наличие кандидатов, рабочие selector-группы и разрешённый доступ к Clash API; причина отказа — в сообщении и логе |
| После ошибки видны старые значения | Данные могут быть последним успешным снимком; восстановите связь и обновите страницу |

При сообщении об ошибке в [Issues](https://github.com/andreydyadyk/nodes-tester/issues) укажите версию OpenWrt, пакета и sing-box, действие и короткий обезличенный фрагмент ошибки. Удалите URL подписок, ключи, токены и приватные адреса.
